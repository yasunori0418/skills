# handoff — セッション跨ぎの引き継ぎ書

長時間ジョブは 1 セッションで完走しない前提で運用する。コンテキスト肥大・中断・
セッション消失のどれが来ても、別セッションの親が正確な位置から再開できるよう、
`tmp_claude/<job>/handoff.md` を生成・更新する。

## 生成・更新のタイミング

- **Phase 2 完了時点で必ず生成する**（wave 0 起動直後が最初の「再開可能点」になる）
- 以降は**状態が変わるたびに更新する**: wave の完了・PR 作成・計画突合の結果・事前裁定の
  追加・既知バグの発見。長時間中断（離席・日跨ぎ）の前には最新化を確認する
- 更新は差分でよい。書き直しに時間を掛けない（引き継ぎ書は成果物ではなく保険）

## 必ず含める内容

実運用で「これがあったから正確に再開できた」と確認できた 4 要素:

1. **再開プロンプトの雛形**: `/job-graph` の明示実行で始めてスキルを確実に
   読み込ませ、**完了済み Phase の再実行を明示的に打ち消す**（例: 「Phase 0〜2 は
   完了済み。spec 起草・plan 承認・wave 0 起動をやり直さず、Phase 3 の監視から
   再開する」）。打ち消しが無いと新しい親は最初から計画を立て直そうとする。
   雛形には「**未確認の裁定があれば最初にユーザーへ確認する**」を含める（前任の親が
   自分だけで下した裁定を、新しい親がユーザー承認済みと誤認して引き継がないため）
2. **親エージェント名**: worker_contract に焼き付いた名前を記し、再開直後に
   **一字一句同じ名前**で rename することを再開手順の先頭に置く（SKILL.md
   Phase 1 参照。違う名前だと report.sh の報告が届かない）
3. **後続 wave の起動コマンド完全形**: plan_orchestration.py が出した COMMANDS を
   **コピペで実行可能な形のまま**貼る（要約・省略をしない。再開後の親に
   再生成させると spec・プロンプトファイルの再現から必要になる）
4. **運用注意**: 既知バグと回避策・API フォールバック・ユーザーから得た事前裁定
   （ワーカーの選択ダイアログへ即答するための判断材料）

加えて現在地を機械可読に: 各タスクの状態（未起動 / working / PR 済み / マージ済み）、
worktree パス、pane ID、境界ファイルの現在の allow、**計画突合の状態**
（`未` / `合格` / `要裁定` / `裁定済み`。`scope-gate.md` の結果）。

## 事前裁定の様式

裁定は**承認の有無を必ず併記**する。親だけで下した裁定と、ユーザーが確認した裁定を
同じ行に並べると、次の親が区別できずに承認済みとして扱う。

```
- 裁定: <内容>  / 承認: ユーザー確認済み
- 裁定: <内容>  / 承認: 親のみ（未確認）
```

- lane-ops の判定基準表で「常にユーザー裁定」に当たるもの（仕様の解釈変更・検査の
  緩和・計画に無い型/関数の追加・計画外変更の許容など）は `親のみ（未確認）` で
  記録できない。ユーザーに確認してから `ユーザー確認済み` で書く
- 覆った裁定は**削除せず** `撤回済み（<日時 JST>）` に更新して残す（撤回の事実を
  知らない親が旧裁定を再適用するのを防ぐ）

## テンプレート

```markdown
# handoff: <job 名>（更新: <日時 JST>）

## 再開プロンプト（コピペ用）
/job-graph <計画ファイル> — Phase 0〜2 は完了済み（spec 確定・plan 承認済み・
wave 0 起動済み）。再実行せず Phase 3 の監視から再開する。まず親を
`herdr agent rename "$HERDR_PANE_ID" <親名>` で改名し、本ファイルの
「現在地」を読んでから watch を張ること。「運用注意・事前裁定」に
`承認: 親のみ（未確認）` の裁定があれば、監視を始める前にユーザーへ確認する。

## 親エージェント名
<親名>（worker_contract に焼き付き。一字一句この名前で rename する）

## 現在地
- <task-id>: <状態> / worktree: <path> / pane: <id> / PR: <URL or 未> / 突合: <未|合格|要裁定|裁定済み>

## 後続 wave の起動コマンド（完全形）
<COMMANDS の該当部分をそのまま>

## 運用注意・事前裁定
- <既知バグと回避策>
- 裁定: <内容> / 承認: ユーザー確認済み
- 裁定: <内容> / 承認: 親のみ（未確認）
- 裁定: <内容> / 撤回済み（<日時 JST>）
```

## セッション全損時

herdr サーバー再起動で session ごと消えた場合の復旧（workspace の同 label 再作成 →
worktree cwd で `claude --continue` → 親 rename のやり直し）は lane-ops の補足を
参照。handoff.md がディスクに残っていれば、全損後もこの手順 + 上記テンプレートの
情報だけで再開できる。
